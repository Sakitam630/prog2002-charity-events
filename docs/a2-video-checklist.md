# A2 demonstration checklist

Record your running application and explain it in your own words. Maximum length:
15 minutes. This is a checklist, not a written report or narration script.

1. Show the charityevents_db schema: organisations, categories, events, keys and
   the eight sample events. Keep passwords and private configuration out of frame.
2. Show event_db.js and the Express routes. Demonstrate GET requests in Postman:
   health, categories, upcoming, combined search, an invalid date and event detail.
3. Trace a frontend request through fetch, the API response and DOM rendering.
4. Demonstrate the homepage, search by one condition and multiple conditions,
   Clear Filters, no results and validation feedback.
5. Open event detail from a result. Show the full information, free/paid tickets,
   fundraising goal/progress and Register's under-construction alert.
6. Show responsive layout and explain why suspended events are unavailable.
7. Verify the recording is readable and under 15 minutes before sharing it.

Suggested time budget: database 2 minutes; API 4; fetch/DOM 2; live website 5;
brief close 1. Leave a buffer rather than exceeding 15 minutes.

If recording without narration for later voice-over, ensure the final submitted
version still explains the database/API, data flow and live functionality.
Upload the final recording to SCU OneDrive and verify the sharing link works for
the marker. Do not assume a link restricted to your own account is sufficient.
